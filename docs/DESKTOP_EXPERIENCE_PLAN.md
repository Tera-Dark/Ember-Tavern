# 余烬桌面体验改进计划

日期：2026-10-12。状态：拥有者已批准，完整计划实施中；本轮完成首页与桌面壳，并推进首次开桌、连接、内容与任务管理，尚未完成全部 A–F 验收。进度与证据见 [执行记录](DESKTOP_EXPERIENCE_PROGRESS.md)。基线：main `d2a44f5`，桌面 / 引擎 `0.2.0-beta.4`、宿主 `2.4.0-beta.1`。本计划面向房主的整个使用周期：安装、开桌、继续冒险、邀请同伴、配置服务、管理内容、更新与恢复。

## 目标与参考

把余烬桌面做成操作连贯、状态可信、视觉精致的房主工作台。用户应能看懂“现在是什么状态、下一步做什么、操作会影响哪些房间和数据”。首次使用和日常继续冒险分别优化。

截图提供的视觉参考：深紫灰背景、低强度光晕、宽搜索框、简洁实例卡片、统一顶栏、清晰的卡片分组与较少的主操作。保留余烬自己的品牌，默认建议深紫灰 / 炭黑背景配余烬暖金强调色，继续支持月下与浅色主题。正式设计时在相同页面比较两套配色。

[当前 Comfy Desktop 官方说明](https://github.com/Comfy-Org/Comfy-Desktop/blob/main/README.md)的流程参考包括独立安装、一键启动、版本更新、快照恢复与导入旧环境。[官方设置实现](https://github.com/Comfy-Org/Comfy-Desktop/blob/main/src/main/settings.ts)也可参考自动启动与关闭行为设计。这里是产品体验参考，余烬继续使用现有 Electron / Vue / TypeScript + Go + FastAPI 架构。

## 当前基础与缺口

| 已有基础 | 当前缺口 | 改进目标 |
| --- | --- | --- |
| 首页、实例卡片、搜索和三套主题 | 卡片点击统一进入管理页；日常启动 / 继续缺少直接入口 | 每张卡片有符合当前状态的一个主操作 |
| 开桌向导与已有冒险选择 | 每次进入实例都落到向导；管理页与向导重复呈现部分信息 | 首次引导，后续优先继续最近冒险 |
| 房间、身份密钥、角色分配 | 分散在多个区域，入口 / 密钥 / 到场状态需要来回核对 | 房间准备页完成邀请、到场与分配 |
| 安装 / 更新任务与日志 | 首页进度和实例任务分散；大量依赖统一 loading 和轮询 | 统一任务中心，每个实例独立状态 |
| API 配置与本机诊断 | 原始字段多；保存、可连接、能生成尚未分开展示 | 连接档案、分层检测、明确收费测试 |
| 插件管理、预设选择、原生导入 | 发现、兼容、安装、授权和启用不够连贯 | 可审阅的内容导入 / 启用流程 |
| 更新、历史版本、数据快照与索引恢复 | 用户仍需理解多种版本与数据恢复语义 | 版本摘要、影响预览、明确恢复对象 |
| 原生控制台与冒险窗口 | 关闭即退出并停服，窗口控制和运行反馈尚不完善 | 明确后台运行 / 退出语义、托盘与窗口状态 |

上述判断来自当前 `App.vue`、`FirstTable.vue`、`VersionManager.vue`、`InstanceDiagnostics.vue`、共享类型与 Electron 主进程；不是来自未经体验验证的功能假设。

## 信息架构

全局层：**首页、内容库、任务中心、应用设置**。通知从顶栏进入，失败和需要处理的任务保留至处理或明确关闭。

实例层：**概览、冒险房间、扩展与服务、版本与备份、诊断与日志**。选中实例后侧栏始终清楚显示实例名称、运行状态和主要入口。

“实例”表示独立服务环境；“冒险房间”表示其中一场保存的游戏。首次使用以“创建酒馆 → 开一场冒险”呈现，技术端口、通道、目录和 commit 收在高级设置或详情中。主界面不要求用户先理解部署术语。

首页优先显示最近使用、运行中、收藏的实例及最近冒险。首次用户看到新建 / 导入入口与引导；返回用户看到“继续冒险”。搜索 / 筛选有真实空结果提示，不把不存在的云服务或推荐作品画成可用功能。

## 关键操作流程

### 首次安装与开桌

打开安装器 → 安装桌面 → 首次欢迎 → 创建酒馆 → 自动检查目录、磁盘、端口和下载条件 → 准备环境 → 选择入门玩法或导入自己的预设 → 创建冒险 → 单人进入或邀请同伴。

- 默认推荐配置可直接继续；数据目录与端口自动建议，允许在高级选项修改。已有数据目录先识别，再选择复用 / 恢复，不覆盖未知文件。
- 创建前显示需要下载的内容、数据保存位置与已知磁盘需求；未取得可靠体积时显示未知，不编造剩余时间。
- 安装页展示下载、校验、环境准备、健康检查等真实阶段；离开页面可继续查看任务。支持的下载阶段可取消，关键切换阶段须保护事务完整性，不能只在前端放一个无效的暂停按钮。
- 演示模式无需 API Key，单人开桌不必先完成邀请步骤。上次未完成的引导可以恢复，已完成的引导不会每次重放。

### 日常继续冒险

打开桌面 → 点击实例的“继续冒险” → 必要时启动服务并等待健康检查 → 进入上次明确选择的房间。

- 无房间时转到新建 / 导入；有多间房时允许换房。不会因刷新、轮询或旧的异步回复改掉用户的新建意图或选中房间。
- 卡片主操作按状态显示“安装并开桌”“启动并进入”“继续冒险”“查看进度”“处理问题”。高风险操作放入更多菜单。
- 同一房间的冒险窗口可复用或聚焦；关闭冒险窗口与停止实例分别处理。关闭控制台时明确提供后台运行、退出并停服与取消，记住偏好；首次说明对同伴的影响。

### 邀请同伴

进入冒险房间 → 选择分享地址 → 创建同伴身份 → 私下复制入座信息 → 同伴入座 → 分配角色 → 开始。

- 地址提供二维码与复制入口；二维码只含入口地址，不默认携带验证密钥。
- 一次性密钥仅生成时展示，不记入浏览器持久存储、日志或诊断包。既有密钥不回显，丢失时使用原有轮换 / 撤销流程。
- LAN / VPN 地址给出来源与选择提示，不只把第一张网卡当作正确答案。端口检查与实际同伴连通状态分别显示。
- 展示待入座、已验证、在线 / 离线、已分配等有权读取的状态；只有服务端提供证据时才显示对应状态，不把“有网卡”说成同伴已连上。

### 配置模型、声音与图像服务

选择用途 → 添加连接档案 → 填入地址 / 凭据 → 选择模型 → 检测 → 保存并应用。

- 普通路径优先“一个决策模型”；知识顾问、声音、图像作为可选服务。按现有实际插件能力开放入口，缺少图像生成模块时只在规划中保留位置。
- 区分未检测、已保存、模型列表可获取、实际生成测试成功。模型列表不受支持时可手填；不能把列表读取成功当作生成成功。
- 真实生成测试是单独的显式操作，显示请求内容与可能费用；不自动使用用户私有测试配置或后台消耗余额。
- 密钥不回显，保留 / 替换 / 清除明确区分。档案共享、运行时注入和系统凭据加密需要独立迁移方案，兼容现有配置与回退版本；不得因新界面改写旧房间的模型模式。
- 运行中配置明确说明是否需要重启，提供保存后应用；存在同伴或任务时展示影响并安排安全重启。

### 内容、插件与作者工具

选择 / 导入作品 → 预览署名、许可、规则和依赖 → 校验兼容 → 显式批准必要权限 → 安装或新建房间 → 按房间启用。

- 内容预设与可执行插件分开呈现；展示缺依赖、未安装、已安装、未授权和已启用等实际状态。
- 导入预设创建新房间；派生作品显式生成新版本，保留原房间内容锁。
- Python 信任与高风险 UI 能力保持明确审阅，目录审核与 SHA256 不替代授权。
- 插件升级先有后端备份 / 迁移 / 回退能力再提供按钮；现有安装器拒绝覆盖的行为不能被界面绕过。
- 作者先获得校验、导出与投稿材料入口；复杂制作 / 发布可用独立创作工作区承接，避免占据首次开桌页面。目录中的本地样板、社区投稿与真实发行分别标注。

### 更新、备份与恢复

看到更新通知 → 查看桌面 / 本体版本和变化 → 预览受影响实例 → 备份与预检 → 应用 → 自动恢复原运行实例 → 查看结果。

- 默认摘要使用发行版本 / tag，宿主版本与来源 commit 可展开；桌面更新、实例本体更新、规则 / 内容锁不混为一种更新。
- 保留成功回退后消除同一新版提示、更高版本再提示的已有行为。
- 恢复页先选实例、目标快照和恢复范围，明确展示会恢复哪个时间点的数据、当前较新进度保存在哪里。剧情回档、数据库备份恢复与版本降级分开解释。
- 提供快照列表、占用统计、保留策略和受保护快照。清理必须显式选择，正在使用或唯一可回退的快照不能被自动删掉。
- 失败时原版保留，结果页提供恢复运行、重试和脱敏诊断入口。下载失败 / GitHub 限流与“已经最新”分开表示。

## 视觉与交互规范

- 统一颜色令牌、文字层级、间距、圆角、边框、阴影、按钮与图标规格。主要正文优先 14–16px，关键任务状态更醒目，弱说明保持可读对比。
- 首页有克制的品牌光晕和留白；实例管理页与日志页提高信息密度。宣传区根据首次 / 返回状态调整，1366×768 下能看到主操作。
- 卡片提供直接主按钮、状态标签、近期冒险摘要和更多菜单；正在运行的实例一眼可辨。
- 弹窗、侧栏抽屉、通知和错误页使用统一组件；停止服务、撤销邀请、回退等操作使用具体影响说明。
- 骨架屏、进度、成功和失败各有明确反馈。动效以 150–250ms 的状态过渡为主，尊重减少动态效果设置，不让动画阻碍操作。
- 窗口具备最大化 / 还原、正确拖拽区、位置 / 尺寸记忆；覆盖高 DPI、键盘操作、焦点恢复和读屏标签。

## 工程实施

保留已有引擎事务、恢复日志、房间版本锁、安全 IPC 与系统加密。按体验领域拆分前端，不重写游戏宿主或更新引擎。

- `App.vue` 收敛为应用壳与导航；分离首页、实例工作区、房间准备、服务连接、任务、版本恢复和设置视图。
- 状态按实例 / 房间分开管理；请求携带明确目标，保留异步过期回复隔离。统一处理断开、重连、权限撤销、重复点击和任务结束事件。
- 引擎先补结构化任务阶段、可重试 / 可取消能力与错误码；前端据此呈现下一步操作。先改善现有轮询与窗口可见性调度，再评估通过认证的事件订阅，保留重连后全量同步。
- UI 偏好可存本地；凭据与服务操作留在受信任主进程 / 引擎。渲染进程不能借新连接、导入或修复按钮获得任意路径、命令或远程执行权限。
- 诊断包使用字段白名单与脱敏导出，默认排除凭据、邀请、数据库和私人剧情；原始日志与可分享诊断分别提供。

## 分阶段交付

| 顺序 | 交付 | 完成条件 |
| --- | --- | --- |
| A：流程与设计规范 | 页面地图、关键流程、状态矩阵；首页 / 安装 / 房间准备 / 更新恢复四页高保真原型 | 首次与返回路径都可走通，风格与信息层级确定 |
| B：首页与桌面壳 | 公共组件、分区导航、实例卡片主操作、最近冒险、窗口管理 | 从首页直接启动并进入正确冒险；旧实例与已有配置保留 |
| C：首次使用与邀请 | 新建 / 恢复向导、真实阶段安装进度、房间准备、同伴信息与角色分配 | 单人可跳过邀请；双端可完成邀请、分配与断线回来 |
| D：连接与内容管理 | 模型连接档案、分层检测、内容预览与插件状态 | 不误报连通、不隐含收费；导入与信任边界可验证 |
| E：任务与可靠运维 | 任务中心、通知、后台运行、更新影响预览、快照 / 恢复与诊断 | 失败可处理；关闭和恢复语义明确；较新进度和原数据受保护 |
| F：整体验收与测试发行 | DPI / 键盘 / 窗口检查、真实安装与完整流程测试、版本文档和不可变测试包 | 从干净机器和旧版本升级各走一次完整链路，记录反馈与尚未验证项 |

B / C 是第一轮可使用交付，D / E 是第二轮。A 的状态设计先于功能改写，精细动效在主要路径稳定后完成。托盘、配置应用和可取消任务需要主进程 / 引擎配合，不按纯 CSS 工作估算。

## 验收指标

以下为目标，不是当前已有测试结果：

1. 不熟悉 Python / Git 的试用者能按引导完成演示开桌，首次流程不强制填写模型密钥、端口或高级部署字段。
2. 已完成配置的用户，从首页一次主操作即可启动并进入最近明确选择的冒险；等待时间单独记录，不把下载速度计入交互步数。
3. 每个异步操作都有可观察阶段、明确结果和恢复路径；同一实例任务互斥，不阻塞其他实例的无冲突管理操作。
4. 1366×768、1920×1080、125% / 150% / 200% 缩放下关键按钮不被截断；键盘可完成主要路径。
5. 断网、GitHub 限流、端口占用、权限不足、实例启动失败、更新失败和恢复中断均有可复现用例及明确保护结果。
6. 旧房间、身份、内容 / 插件锁与加密凭据不因视觉重构发生变化；日志 / 诊断没有秘密泄露，模型检测没有隐藏付费请求。
7. Windows 原生测试覆盖新装、已有实例、多人房间、停止 / 后台运行、更新与回退。模拟发行、实际下载安装和真人试用分别记录。

首批建议从 **A → B → C** 推进：先交付统一风格的首页、真正可用的“继续冒险”和顺畅的首次开桌，再完善连接、内容与运维工作区。
