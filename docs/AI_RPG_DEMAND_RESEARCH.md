# AI 跑团 / 酒馆需求调研与产品推论

日期：2026-10-01。服务于 [开发计划](DEVELOPMENT_PLAN.md)，不是全市场份额调查。这里的“酒馆”主要指 SillyTavern 角色卡 / 世界书 / 扩展生态；余烬的实际多人房间需求另行验证。

## 1. 证据怎么使用

本次查阅了官方产品文档、公开创作者仓库 / issue、公开社区讨论和卡库。**没有可核验的跨平台活跃人数、玩法留存或完整下载统计，因此不宣称“大家最喜欢”的数值排名。** 未进入封闭 Discord 获取私人聊天，也不采集个人聊天正文。

- 官方文档：可以确认功能和限制，不能证明某玩法最热门。
- 社区帖子：说明有人有该需求，不能推断全体占比；有自选样本和平台偏差。
- 卡库分类 / 下载展示：说明题材供给和站内表现，不等于持续游玩、更不等于多人跑团留存。本站 AI 评分也不是用户偏好调查。
- 作者仓库 / issue：说明可复用创作模式与具体技术痛点，不代表代码安全、实现完整或广泛采用。
- 商业产品自己的“最佳”“无限记忆”“完美规则”宣传不作可靠结论依据。

下列“高优先级”是结合证据、余烬现有基础与小团队成本的**产品建议**，不是热度排名。

## 2. 可以确认的需求信号

### 角色互动、场景与多 NPC

SillyTavern 官方把角色卡作为核心概念；卡可以代表人物，也可以代表抽象场景。其能力包括世界信息、个人身份、群聊和社区扩展。[1](https://docs.sillytavern.app/)

2026 年 6 月公开“最佳角色卡”讨论里同时出现奇幻 / 穿越冒险、RPG、日常聊天和自建设定卡的推荐，说明偏好并非只有一种。[1](https://www.reddit.com/r/SillyTavernAI/comments/1tur2qi/your_best_character_cards/) 一个公开卡库的分类也覆盖 Adventure/RPG、Fantasy、Sci-Fi、Horror/Thriller、Romance、Slice of Life 等；只能当作题材供给证据。[5](https://wp.aicharactercards.com/)

**对余烬的推论**：提供有动机、记得关系、会回应世界事件的 NPC 和开场钩子，比先增加一百个属性更重要。关系叙事 / 日常不应强制掷骰；奇幻冒险可选轻规则。多人是真人共同参与，不等同于多 AI 角色自动对话。

### 长故事、世界一致性、可见状态

AI Dungeon 官方说明，有限 context 需要摘要、记忆存储与检索协作；其 Story Cards 按关键词注入，Plot Essentials / 摘要等承担不同用途。[1](https://help.aidungeon.com/faq/the-memory-system) 官方还展示所需信息超出 context 时的裁剪与动态预算机制，不能把“数据库保存了所有事件”称为模型始终记得全部事件。[4](https://help.aidungeon.com/faq/what-goes-into-the-context-sent-to-the-ai)

中文记忆增强扩展提供可共享表格结构与配置，是作者把重要状态可见化的一种实践。[8](https://github.com/muyoou/st-memory-enhancement) 另一个 2026-09-30 的公开需求 issue 直接指出：金钱、声望、技能、图鉴、势力关系等长尾数据不应都迫使世界作者再写一个新插件，希望用声明式结构和通用面板维护。[5](https://github.com/ackness/covel/issues/96)

**对余烬的推论**：优先做“结构化事实 / NPC 关系 / 任务与资源面板 + 带来源的会话摘要 + 可解释上下文选择”。通用声明式状态应支持零代码内容作者，但模型只能提议更新，不能绕过校验直接结算经济、骰子或权限。摘要是有损信息，不是新的权威原始事件。

### 世界书创作与排错

SillyTavern 官方明确：World Info 能引导模型，却不保证模型在输出中遵守；条目需要自足，正文以外的标题 / 激活关键词不必然进入提示，并建议简洁内容与预算管理。[1](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)

早期新手帖子中出现“已导入但是否真正触发不清楚”的问题，以及通过 prompt 检查和关键词设置排查的经验。这是个案，不是当前故障率统计。[10](https://www.reddit.com/r/SillyTavernAI/comments/198gr11/rookie_here_hoping_you_can_give_me_pointers/)

**对余烬的推论**：作者工具应显示“为什么激活 / 未激活 / 被预算排除”，提供测试句、秘密预览、模拟导入和字段帮助，而不是只把 JSON 校验成功当作作品可玩。

### 变量驱动、模拟与创作者门槛

公开 MVU 扩展展示变量管理、更新历史、状态快照及 AI 输出提议驱动变量更新的模式。[2](https://github.com/smAI42/mvu-sillytavern-extension) 中文新手求助里也有“MVU 是什么、没装到、图像来源与费用怎么选”的具体例子，说明堆叠扩展和服务会增加入门成本。[10](https://tieba.baidu.com/p/10459059755)

**对余烬的推论**：经营 / 生存 / 成长应从少量可见字段和可复用动作开始；“一个预设就能开桌”比要求安装若干脚本、填很多提示词更符合我们的核心要求。类 SLG 值得做试验，但本次证据不足以证明它是酒馆最高热度类型。

### 规则、骰子与协作

SillyTavern 官方群聊是多个 AI 角色与用户的共享历史；合并角色卡也可能产生身份 / 人格混淆。[3](https://docs.sillytavern.app/usage/core-concepts/groupchats/) 这不能替代真人多人房间的操控权、提交顺序、权限与冲突管理。

玩家对 ChatGPT 当 DM 的公开体验提到角色 AC / 名称等会出错，需要独立角色记录；这只是单篇经验，不是所有模型的统一失败率。[5](https://3wisedms.com/our-final-thoughts-the-5-pros-and-cons-of-the-chatgpt-dungeon-master/)

**对余烬的推论**：我们应发挥已有权威事件 / 骰子 / 角色分配的优势。系统负责可靠计算，AI 负责叙事与意图理解；多人支持提出行动、确认参与者、轮次结算、人工修正和断线回来，而不是每个玩家发送一句后立刻让 AI 抢先推进。

## 3. 首批玩法候选：按适配度，不按假“热门榜”排序

| 方向 | 玩家想得到什么 | 预设 / 系统重点 | 建议 |
| --- | --- | --- | --- |
| 奇幻小队 / 地城 / 穿越冒险 | 探索、同伴、成长、选择后果 | 世界书、NPC、任务、道具、轻规则 | 第一批；原有雾港 / 边境可延续 |
| 悬疑调查 / 恐怖气氛 | 寻找线索、推理、有代价的选择 | 线索图、公共 / GM 信息、失败继续推进 | 第一批；不冒称完整 CoC |
| 日常 / 关系 / 角色群像 | 独特 NPC、关系与生活推进 | NPC 关系、地点、日历、风格 / 同意边界 | 第一批可选，不强制战斗 |
| 生存 / 商队 / 小型经营 | 看得见的成长、资源取舍 | 物资、制作 / 交易、事件与结算日志 | 第二批，共用通用状态基础 |
| 5e SRD 小队 | 公平检定、战斗与角色能力 | 受测试的规则适配器、角色 schema、战斗轮次 | 独立规则实验，先小范围 |
| 类 SLG 城邦 / 据点 | 建设、外交、领地和回合规划 | 经济、回合、势力、地图、确定性账本 | 实验库，从合作经营起步 |
| 完整 PvP SLG / 超大 4X / 全规则百科 | 对抗和规模 | 私密视野、AI 势力、平衡、性能与大量授权内容 | 暂后；不作为首轮验收目标 |

同一题材可以使用不同规则和表现，例如“边境商队”既能是叙事冒险，也能是回合经营。题材标签与玩法类型不能合并成一个字符串或强迫绑定一套 UI。

## 4. 从信号到真正验证

建议第一轮邀请 8–12 位愿意参与的人，覆盖自由 RP / TRPG 玩家 / 世界作者，至少组织 3 桌真实试玩。样本是试点，不推断全市场。

1. 每人先选想玩的方向，再观察实际能否开桌，不只问“会不会用”。
2. 同一位参与者试 2 个短场景，轮换顺序，避免先试玩的预设天然占优。
3. 记录零帮助入座率、设置时间、每十轮人工纠错次数、记忆 / 规则 / 卡顿痛点、能否第二次回来。
4. 作者尝试不修改核心代码制作新世界、换开场、调整一个状态和发布包，记录在哪一步需要帮助。
5. 经营 / SLG 若只“觉得概念不错”但试玩无资源取舍、无第二场意愿，暂停扩大开发；优先满足已经发生的需求。
6. 用户选择加入才采集事件类型、耗时、错误码和计费统计；默认不上传剧情正文 / 身份密钥 / 世界书秘密，不抓封闭社区个人聊天。

比较重点：**完成第一场 → 状态可信 → 第二场能继续 → 创作者能做第二个作品**。截图好看、卡库下载、仓库 stars、模型营销榜不能替代这四项。

## 5. D&D / 内容许可注意

本次查阅的官方 SRD 5.2.1 使用 CC BY 4.0，要求规定的署名；许可是该文档，不等于所有 D&D 书、插画、世界设定和商标都可自由分发。[1](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf)

建议先做注明适用版本、范围与来源的“5e SRD 子集”规则包，官方发行使用原创剧本与素材。不把未授权 IP 角色、商业模组扫描件、社区作者作品或别的平台脚本复制进默认预设库。社区发布需要作品级许可 / 来源 / 举报 / 下架机制。

## 6. 本次刻意不作的结论

- 不宣称 romance、奇幻、NSFW、SLG 或 D&D 任何一类拥有全社区第一的用户占比。
- 不把商业 AI DM 平台的“无限记忆”“完美规则”作为能力基线。
- 不把多 AI 群聊当作多人在线跑团；不把带骰子按钮当作完整规则引擎。
- 不据此引入任意 EJS / 正则脚本执行、绕过内容安全的提示或默认安装外部代码。
- 不追求一次兼容 SillyTavern 的所有可执行扩展；先明确支持的数据字段、转换丢失和禁止执行内容。
