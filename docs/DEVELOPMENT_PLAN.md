## 3. 总体取舍：先可靠开一桌，再扩大玩法

公开社区能确认角色互动、奇幻 / 场景冒险、世界书、记忆、变量 / 状态等需求信号，但无法得出全社区玩法排行。官方文档也明确世界信息不能保证模型遵守，模型 context 有限。[1](https://docs.sillytavern.app/usage/core-concepts/worldinfo/) [1](https://help.aidungeon.com/faq/the-memory-system)

因此优先级如下：

1. **P0：可安装、可恢复、少设置、能继续上一场。**
2. **P1：玩法预设契约、创作者文档 / 工具、完整开桌路径。**
3. **P2：世界 / 任务 / NPC / 资源状态可信，规则适配器可扩展。**
4. **P3：少量可完成的 5e / SLG 样板与社区预设库。**
5. 不优先做复杂商城、云多人集群、所有规则大全、完整 4X、任意代码沙箱或节点式万能编程器。

“易用”和“文档”不是最后的美化阶段，必须出现在每一个里程碑的验收中。

## 4. 四层可组合架构

```text
桌面控制台 / 玩家浏览器 / 创作工坊
                  │
       玩法预设：声明组合和默认设置
       ├─ 世界书 / NPC / 角色模板 / 剧本与开场
       ├─ 规则包绑定 + 所需模块 / 精确版本
       └─ 表现配置 / 难度 / 叙事风格（不含密钥）
                  │
    已审阅规则适配器     插件资源与 UI / 声音 / 地图
                  │
       宿主命令、校验、权限、幂等与事件
                  │
     可版本化状态 / 分支快照 / 素材与内容锁
```

### 边界

- **宿主**：身份、房间、权限、角色控制、提交事务、事件与回档、可信随机数、最小任务生命周期。保持小。
- **规则适配器**：规则特定状态 / 命令 / AI 提议 schema、校验、结算、迁移；不能改变账号权限。
- **通用模块**：任务、NPC 关系、物品、地图、经营、台本 / TTS、UI。通过版本化资源交互，不访问别人内部字段。
- **内容 / 预设**：作者写设定、剧情和组合，不自行执行代码。模型连接与凭据保存在本机单独配置。

同一题材可以选不同玩法：边境商队既可做轻规则调查，也可做合作经营。规则、题材和外观不能绑死。

## 5. 预设库设计：不是角色卡堆放区

### 5.1 分清五种东西

| 名称 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 世界书 | 世界事实、地点 / NPC / 阵营、公共 / GM 资料 | 不执行结算，不携带玩家账号 |
| 角色卡 | 可复用角色 / NPC 描写及规则相容的初始数据 | 不携带现有操控权、会话或完整存档 |
| 剧本 / 场景 | 开场、目标、线索 / 阶段、失败分支、结局条件 | 不强制 AI 替玩家作决定 |
| 玩法预设 | 把世界、剧本、角色、规则、模块与默认设置组合 | 不自动授权 Python / JS、不含 API key |
| 存档 | 当前玩家、事件、运行状态、内容版本锁与分支 | 不是可直接公开的创作包 |

酒馆中的生成“预设”经常指提示词 / 采样设置；余烬界面应单独叫 **玩法预设** 和 **叙事 / 模型配置**，避免概念混淆。

### 5.2 初始设计（实现以 M1 契约为准）

M1 已新增 `ember.preset/v1` 和 `ember.scenario/v1`，不修改现有 v1 文件语义。初期复用原 worldbook / character / theme 契约。

```text
frontier-caravan/
  preset.json          # 名称、作者、许可、玩法、精确依赖、文件散列
  world/worldbook.json
  scenarios/opening.json
  characters/scout.json
  characters/trader.json
  README.md
  LICENSES/            # 本包及每项引用内容的许可 / 署名
  tests/               # 测试行动、关键事实、期望状态 / 结局
```

拟议清单字段：稳定 ID、作品版本、格式版本、作者 / 来源 / 许可、语言、封面、题材、玩法、建议人数 / 时长、难度、成熟度、内容提醒、规则 ID / 版本、必需和可选插件、相容宿主 / API、各内容文件和 SHA256、默认 UI / 叙事风格、离线 / 网络 / 可能费用说明。**此段是初始设计，不代表每个字段均在 v1 采用；实际契约 / CLI / 范围以 [作者教程](PRESET_AUTHORING.md) 和 Schema 为准。**

- 使用受限相对路径、文件数 / 大小 / 解压上限、拒绝 symlink / 穿越、明示不支持格式；不执行包内脚本。
- 依赖引用可审阅插件包；若缺少代码模块，单独走插件授权。导入数据包不能默默安装 / 信任代码。
- 选择预设时展示人数、难度、系统、费用、内容提醒、缺失依赖和权限；一键 **创建新房间**，事务失败不留下半套配置。
- 已有房间先只支持添加明确的内容组件；不在进行中的游戏一键切规则 / 覆盖世界。后续需要备份、变更预览和迁移。
- 房间生成 `content lock`：使用的作品 / 规则 / 插件精确版本与散列。作者升级不自动改变旧房间；更新需备份、兼容检查和明示确认。
- `.env`、连接 profiles、token、身份密钥、玩家数据不进入公开包。GM 秘密可属于剧本，但需要标记；它不是能存私人凭据的保险箱。

### 5.3 首批库：3 个可稳定试玩 + 2 个实验

| 预设 | 玩法 / 规则 | 最小内容与完成条件 | 分级 |
| --- | --- | --- | --- |
| 雾港：最后一班渡船 | 合作悬疑，ember-light | 少量地点、3 个主要 NPC、多个线索入口、至少两种结局；一场可收束 | 推荐样板 |
| 余烬边境：失联商队 | 探索 / 奇幻小队，ember-light | 角色模板、任务与物品、一次可协商 / 潜入 / 战斗解决的遭遇 | 推荐样板 |
| 小镇的一周 | 日常 / NPC 群像，叙事模式 | 日历、关系与承诺、不同人物诉求；不必战斗 / 掷骰 | 推荐样板 |
| 遗迹小队 | 指定版本 5e SRD 子集 | 少量等级 / 职业与支持法术、一次完整遭遇 / 休息；不支持规则明确拒绝或交人工 | 规则实验 |
| 灰烬城邦 | 合作回合经营，原创 SLG-lite | 4 种资源、3 类建筑、少量地区 / 外交事件、8 回合目标、资源结算可解释 | 策略实验 |

这些是建议选题与验收范围，不把尚未编写的作品显示成可下载。官方样板使用原创剧情 / 素材，第三方可发布科幻、修真、生存等变体。第一批不追求几十套半成品。

## 6. 规则与通用状态：多玩法的真正前置

### 6.1 通用声明式状态

先支持零代码作者声明：字段类型、默认值、范围、单位、来源、可见级别、允许操作角色、是否运行时新增实体、面板显示方式。可复用样板：任务 / 标记、NPC 关系、金钱 / 声望、资源 / 建筑、阵营关系。

- AI 输出受限更新提议；服务端验证类型 / 边界 / 引用 / 权限 / revision / branch 后提交。
- 每次变化有动作 / 事件来源；玩家 / 房主的手动纠正也入账，不静默覆盖。
- 权限、骰子、角色控制、付费配置不开放为通用可修改变量。
- 作者可写更新语义帮助叙事；严格经济 / 战斗仍必须由规则算法计算。不能复制“模型直接 JSON Patch 任意状态”作权威结算。
- 初期不提供 eval / EJS / 任意 SQL 或通用可执行表达式语言。

### 6.2 规则适配器演进

先设计受审阅的扩展入口，而不是让任意插件修改 `core.*`：

1. 规则身份 / 版本、状态 schema、角色 schema、行动 / 提议 schema、上下文只读视图。
2. 验证行动 → 生成受限效果 → 权威随机数与规则结算 → 原子事件提交。
3. 统一 `expected_revision / branch / request_key`，可重放和拒绝过期提议；一个房间绑定一套规则。
4. 每个适配器提供旧状态迁移、冻结版本、解释性结算和黄金测试。
5. GM provider 读当前规则契约，不能靠自身文本绕过它。未支持的指令明确提示，允许房主手动裁决但必须留下记录。
6. 对外需要破坏性 SDK 改动时先 RFC / 版本升级 / 迁移，不在 Plugin API 1 下悄悄换语义。

新增资源如 `encounter.turns/v1`、`campaign.quests/v1`、`campaign.npcs/v1`、`economy.resources/v1`、`strategy.map/v1` 都先确定所有者、公开投影、读写能力和兼容性，再实现提供者与 UI。

### 6.3 5e 与 SLG 两条竖向样板

**5e：**先确定规则代际。建议从本次可查的 SRD 5.2.1 子集开始，但 2014 / 2024 选择仍由维护者定案，不混用。第一阶段只做有限等级 / 职业 / 法术、先攻、攻击 / 伤害、优势劣势、基础状态、资源 / 休息和解释日志；不承诺全部职业、专长、反应链或全书内容。现有轻规则 hp / attributes / Decision 的固定形状不能直接代表完整 5e。

官方 SRD 5.2.1 提供 CC BY 4.0 内容及署名要求，但不是对全部 D&D 作品 / 商标的授权。[1](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.1.pdf)

**SLG-lite：**先做合作经营，共享公开资源，不先做 PvP / 私密视野。玩家规划动作 → 房主 / 回合协调器锁定 → 服务端统一计算生产 / 消耗 / 建造 / 交易 → 验证随机事件 → 提交回合事件 → AI 解说与 NPC 外交。事件只能走受限规则效果，不因一段叙事凭空加粮食。存档 / 回档应还原资源、队列与回合，幂等键防止重复结算。

如果没有可见取舍、稳定结算和一场能结束的目标，不扩大为 4X。

## 7. AI 体验：可靠、可控，不承诺“无限记忆”

- **简单连接模式**：默认演示；先提供一个 OpenAI-compatible 决策模型就可开始的方案，知识侧作为可选增强。保留双模型高级模式，不强制新手同时设置两家服务。
- **连接诊断**：明确服务 / 模型 / 能力、超时和常见错误。真正生成测试必须用户点击、注明可能收费；不自动探测付费模型。
- **三层记忆**：结构化权威事实 / 任务 / NPC 状态；带原事件 ID 的会话摘要；当前分支相关事件 / 世界条目检索。先复用词法与关键词，必要时再加可替换向量模块。
- **静态世界与动态战役分开**：AI 建议新增或修改事实，先进入战役状态 / 待审阅区；不自动重写作者原始世界书或其他房间。
- **玩家自主**：AI 描述结果和选择，不替玩家说话或作不可逆选择；失败可以推进剧情而不是所有场景都卡在一次骰子。
- **多人行动**：叙事自由提交 / 小队讨论 / 轮次收集是不同模式；显示谁已提交、当前参与角色、何时结算，提供人工推进、超时和掉线政策。
- **任务生命周期**：请求的 pending / running / completed / failed / cancelled 有持久身份；重试不得重复扣资源。外部模型调用的计费不能假装可回滚或 exactly-once。
- **费用**：展示实际返回的 usage 与累计请求；无 usage 时标未知。用户配置价格才估算金额；设置每房 / 会话预算及停止策略，外部调用前预留上限，明确它不等于供应商账单的绝对硬上限。
- **诊断私有**：房主可查看激活条目与原因 / 截断情况，不给玩家发送 GM 秘密、原始 key 或全 prompt。

| 声明式状态作者 | 自定义任务 / 资源 / 关系与面板 | 字段 / 可见性 / 更新语义、约束与例子 |
| UI / 模块作者 | 用公开 SDK 加面板、资源与动作 | UI 与 Python 分开入门、完整例子、权限 / 回档 / 调试 |
| 规则开发者 / 维护者 | 正确结算、升级、发布和兼容老房间 | 规则 RFC、命令 / 事件合约、迁移、测试、发布与安全 |

### 文档最低交付清单

1. **世界书实战**：从一页设定拆成可自足的地点 / NPC / 阵营 / 规则条目；ID、keys、activation、priority、visibility 的实际效果；预算排错；导入 / 导出与版权。
2. **角色 / NPC 实战**：人物动机、语气、已知信息、关系、初始状态；模板和运行时状态区别；角色不携带玩家操控权。
3. **剧本设计**：场景目标、多个线索入口、失败推进、阶段与结局，不写只允许一种解法的剧情铁轨。
4. **预设教程**：选规则 / 模块 → 组合 → 测试 → 校验 → 发行；版本锁、依赖缺失与费用提示。
5. **插件从零到发行**：公共只读 UI → 自己 namespace 的受验证写操作 → 资源协作 / 骰子 → 可信 Python；每步独立可运行。
6. **规则适配器**：只有入口落地后才编写真实 SDK 教程，提供 5e / SLG 小样板与状态迁移测试，不发布伪接口。
7. **参考与排错**：生成 schema / API 字段表、SDK 能力矩阵、权限、并发 / branch、存档 / 回档、素材、日志和外部服务。
8. **作者许可 / 发布**：署名、派生与来源、打包 / SHA256、测试证据、社区提交、升级 / 下架与维护。

### 文档验收，而不是“写了就算”

- 世界作者用指南，在 30 分钟目标内完成模板的有效修改 / 导入预览 / 试玩；此为试点目标，不承诺每个人的创作速度。
- 开发者只用公开 SDK 做一个独立插件，不改 `server/app.py` / `web/src/App.jsx` / 父 DOM。
- 每个教程带一个可校验样例、测试步骤和典型错误；CLI / schema / 文档版本由 CI 检查。
- 新增公开字段或方法的 PR 必须同时修改文档 / 示例 / 测试；版本快照与当前指南有明确区分。
- 无障碍 / 手机阅读、截图与示例审阅不能只依赖 schema 是否合法。

**当前可用的世界书起步命令**（与拟议 preset 命令分开）：

```bash
python scripts/creator.py init worldbook creations/my-world --id my-world --name "我的世界"
python scripts/creator.py validate creations/my-world/worldbook.json
```

写作原则：短而自足的事实，人物有目标和矛盾；keys 是激活线索而不是正文；少量全局规则用 always，地点 / NPC 多用关键词；剧本秘密标 gm，但模型看到后仍可能泄露，不放真正私人信息；文字“资源扣 3”不等于规则算法会执行。

## 9. 生态闭环与治理

```text
发现作品 → 查看样例 / 兼容 / 许可 / 费用 → 导入预览
→ 明示缺失代码依赖和信任 → 创建新房间 → 试玩 / 反馈
→ 作者派生 / 测试 / 发布 → 版本锁 / 安全升级 / 归档
```

1. **先本地 + 可审阅 GitHub 索引**，不要立刻运营商业市场。索引同时支持世界书、角色、主题、剧本、玩法预设和代码插件，不混淆类别。
2. **默认不开未知代码**；数据包与 UI 能力、Python 执行授权不同。SHA256 证明完整性，不证明作者身份或安全。
3. **分级**：官方推荐 / 社区已试玩 / 实验 / 不兼容 / 已归档；分级有公开标准和测试证据，不因作者名 / stars 自动“认证”。
4. **元数据**：作者 / 维护者、真实来源、许可 / 派生关系、版本与依赖、内容提醒、可能费用、维护状态、问题渠道。
5. **准入 CI**：契约 / 路径 / 大小 / 散列、许可证声明、公开 / GM 投影、依赖冲突、已支持宿主、示例新建 / 导入导出 / 存档回档。代码审计不能被 schema 测试取代。
6. **版权门槛**：当前只有 `LICENSE.example`，不是正式许可证；拥有者应先定代码许可，并为官方内容 / 例子单独声明许可，再邀请社区再分发。未经授权商业模组和素材不进入官方库。
7. **社区机制**：作者入门 issue 模板、作品提交模板、BUG / 兼容报告、举报 / 下架、破坏性变更 RFC、弃用期与迁移样例。
8. **隐私 / 内容边界**：默认适合公开展示的示例，明确内容提醒与作者责任；不上传剧情 / GM 秘密做热榜，不收集玩家私人资料来判断热度。

## 10. 分阶段里程碑与验收门槛

时间仅作为 **1–2 位主力开发者、已有基础且兼做测试 / 文档** 的工作量预估；不等于日历承诺，可并行的作者内容不代替工程验收。每阶段必须先过门槛，才扩范围。

| 阶段 | 建议投入 | 交付 | 通过条件 |
| --- | --- | --- | --- |
| M0 稳定 / 入门 | 1–2 周 | 旧索引诊断恢复、凭据 / 数据恢复设计、版本发布闭环、LAN / API 自检、开桌向导与教程 | 合法 / 非法混合索引不丢诊断证据；不能删数据“修复”；实际机器重复开关 / 升级 / 断线正常；新版本 EXE 与提交一致 |
| M1 创作与玩法预设 | 2–3 周 | preset / scenario RFC 与 v1、组合加载、3 个轻量样板、世界 / 剧本 / 预设作者指南 | 一个新房间完整导入或完全回滚；缺依赖不给半成品；手机入座；作者不改核心做第二个作品 |
| M2 状态 / 记忆 / 规则入口 | 2–4 周 | 通用声明状态、任务 / NPC / 资源面板、摘要来源与预算、多人行动模式、审阅规则适配器入口 | 跨 3 场共 60 个测试行动的关键事实仍正确；封存未来不进记忆；同请求不重复结算；当前与上版存档迁移可测 |
| M3 玩法竖向验证 | 每条 2–4 周，建议顺序做 | 5e SRD 子集、合作 SLG-lite，各一个实验预设 | 一场有目标能结束；战斗 / 经济有确定结算与黄金测试；非法提议不污染状态；不支持规则如实提示 |
| M4 社区生态闭环 | 2–3 周 + 持续维护 | 索引与发现、兼容 / 分级 / 更新、完整作者 SDK 与 CI、投稿 / 举报 / 维护流程 | 至少 3 位非核心作者制作 / 发布可玩的不同作品，至少 1 个独立模块无需宿主改码；升级不改变旧房间 |

M0 可考虑新的桌面 `0.2.0-beta.2`；后续宿主 / SDK 版本要按实际兼容性决定，不提前承诺 1.0。5e 与 SLG 不是必须同时上线。

## 11. 第一轮可直接拆 Issue 的任务

| 顺序 | 任务 | 代码 / 文档入口 | 交付 / 验收 |
| --- | --- | --- | --- |
| 1 | 旧实例诊断 / 隔离 / 恢复 RFC + 测试 | launcher/internal/engine/types.go、恢复模块、desktop | 无效 ID 不能构造路径；备份原索引；有效行继续加载；显式诊断旧行；保存 / 重启仍可找回证据 |
| 2 | 版本与不可变发布 | desktop/package.json、Go version、manifest、desktop.yml | 标签从审定版本取值，源码 / 二进制对应；发布策略不长期写死会话分支；拒绝覆盖；Windows安装 + SHA / smoke 全过 |
| 3 | 房主开桌 / 同伴入座旅程 | desktop renderer、web guest、网络自检 | 环境就绪后房主主动设置目标 ≤5 分钟，同伴目标 ≤60 秒；不把下载耗时藏掉；身份密钥不放 URL |
| 4 | 简单 API 模式与费用 / 诊断设计 | server/ai.py、config、desktop settings | 演示无外部调用；单模型和双模型明确；测试调用显式同意；不回显 / 记录 key |
| 5 | 正式许可证与文档入口 | LICENSE、docs index、版本检查 | 拥有者确认代码 / 内容许可；当前文档与历史快照区分；新人能找到自己那条学习路径 |
| 6 | preset / scenario RFC | server/contracts、content、registry、creator | schema / 语义限制 / 内容锁 / 权限 / 失败回滚先评审；明确不执行包内代码 |
| 7 | 创作工坊编辑与可解释测试 | web/src/content、导入预览、retrieval | 世界条目测试句 / 激活原因 / 预算 / 秘密预览；不需要真实模型即可静态排错 |
| 8 | 两个现有世界改成可完成样板 | 原创 world / scenario / character 内容、教程 | 雾港 / 边境各 1 场测试路线、多解法与失败推进，3 桌真实反馈 |
| 9 | 状态与命令边界 RFC | rules、state、schemas、plugin_runtime | 不允许插件随意写 core；角色 / 资源可迁移；纯叙事提议与严格结算分离 |
| 10 | 5e / SLG 各一个限范围原型 | reviewed adapters、版本资源、实验 preset | 先锁规则版本 / 支持清单再写实现；证明不同循环可跑在同一宿主 |

前 5 项是近期维护 / 易用性，6–8 是最有价值的新功能切片。建议**先交付“预设选择 → 创建房间 → 角色模板 → 身份密钥入座 → 完成一场 → 保存继续”的完整竖向闭环**，不要把所有模块都开工到一半。

## 12. 验证产品是否变得更好

以下为待设定 / 试点目标，不是现有指标：

- 8–12 位试点中，至少 80% 能按指南完成基础旅程，无开发者实时指导；记录失败原因，而不是凑通过率。
- 同伴只需要浏览器；正确密钥可重连，撤销后不得通过旧邀请码 / 回档复活成员。
- 至少 3 桌真实试玩；完成一场后愿意回来继续，比“下载 / 点赞了”更重要。
- 三场 / 60 行动的确定性测试检查关键事实、任务、资源与分支；真实模型另外进行人工评分，不用模拟成功冒充模型表现。
- 每十轮人工纠错次数 / 卡顿 / 无法决定下一步 / 费用疑惑有分类记录，允许逐步降低而不是承诺为零。
- 新作者只通过模板 / 文档做第二个预设；新模块只用公开契约；核心代码改动是否越来越少。
- 同一版本内容 / 规则 / 插件 + 事件可复现机械结果；付费叙事文本不保证完全复现。
- 默认本地保存；任何使用统计都由用户选择，不收集原始剧情、密钥和秘密世界资料。

## 13. 主要风险与延期项

- **玩法太多、规则不实**：先 3 个小样板、再 2 个实验；不宣传“完整 D&D / CoC / 所有 SLG”。
- **插件接口万能化**：小内核 + 审阅规则 + typed command，不用任意执行表达式解决所有问题。
- **模块越多越难用**：预设带最小依赖和默认 UI，高级开关渐进展示；关闭可选模块仍可完成基础冒险。
- **记忆 / AI 权威混淆**：摘要可纠正，原始事件和确定性规则才是依据；AI 看见 GM 秘密后仍不能保证不泄露。
- **内容版本更新毁旧档**：锁精确版本、备份、迁移、试运行、明确降级限制。
- **社区版权 / 安全债**：先正式许可与审阅流程，再扩分发；Python 不叫沙箱。
- **维护负担**：数据库迁移、素材 GC、缓存、卸载 / 降级和依赖求解逐项补，不先造付费商城、集群或大规模战棋。

待拥有者定案的关键选择：代码 / 内容许可、5e 规则代际、首批叙事 / 调查 / 日常比例、首个 SLG 是合作据点还是个人势力。其余基础工作不依赖这些选择，可以先按 M0 / M1 推进。
