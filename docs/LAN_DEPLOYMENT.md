# 一张桌子、一台共享服务器：局域网与部署

适用宿主 2.2.0-beta.1。你和几位朋友使用时，先不需要公网账号系统或多个服务实例。

## 1. 可信局域网的最短路径

房主按 [快速启动](../QUICKSTART.md) 安装依赖，只运行一个服务：

```bash
python -m uvicorn server.app:app --host 0.0.0.0 --port 8000 --workers 1 --ws-max-size 65536
```

1. 房主本机打开 `http://localhost:8000`，注册账号、创建房间。
2. 找到房主电脑**正在使用的局域网网卡 IPv4**：Windows `ipconfig`；Linux `ip addr`；macOS 从网络设置查看。不要选 127.0.0.1 或无关虚拟网卡。
3. 同伴连接同一可信网络，打开例如 `http://192.168.1.20:8000`（换成实际 IP），各自注册／登录，再输入房主邀请码。
4. 房主在角色档案分配操控者，每人一个角色；在模块中心按需开地图／台本／TTS。
5. 用「邀请同伴」暂停新成员、重置邀请码、移除成员；邀请码不能跨两个独立数据库使用。

通过 LAN IP 访问的浏览器会生成对应 LAN 邀请链接。房主用 localhost 时，系统会警告该链接只适用于本机；此时发实际服务器地址 + 邀请码。普通 LAN HTTP 页面可能没有 Clipboard API，复制失败时选中邀请链接手动复制，不必降低浏览器安全设置。

系统防火墙如需规则，只允许端口 8000／受信私有网络；不要关闭整个防火墙。路由器 AP／访客网络隔离可能阻止设备互访，用适当可信网络，不要盲目开放公网端口。建议固定 DHCP 租约，避免重启后 IP 变化。

**LAN HTTP 不加密账号与游戏数据。**仅用可信网络、独立测试密码、无付费密钥试玩。公共 Wi-Fi、不可信 LAN、远程正式使用优先 VPN／TLS，不能把“局域网”当作绝对安全。

## 2. 不在同一网络

优先可信 VPN／组网，让大家仍访问同一个服务器地址；或部署一个 HTTPS 域名。不要每位朋友在自己机器开酒馆后互发邀请码，也不要把浏览器 API 写成 localhost 去调用房主电脑。

前端使用相对 `/api`、`/plugin-frame`、`/ws`，自动适配实际 origin。Vite 开发时由服务器代理后端；浏览器不用跨端口直接调用后端，也不需要关闭 Origin／iframe 隔离。

## 3. 单 worker 是硬要求

SQLite WAL、游戏锁、插件锁、频率计数和 WS Hub 位于单个进程。`--workers 1`，一个 DATA_DIR 对应一个正在运行的实例；不要多个实例共写同一个目录。当前每房间最多 12 位成员、12 个角色。

多个 worker 会让锁、邀请断连和广播不一致。需要多人服务器／多机器时先增加共享协调、消息总线和数据库方案，不是简单改 uvicorn 参数。

## 4. 反向代理与 WebSocket Origin

`deploy/Caddyfile.example` 是**宿主机上的 Caddy**示例，后端仅从本机代理访问。替换真实域名、配置 DNS／TLS，验证 HTTP 与 WS 都经过代理。

WS 对浏览器 Origin 检查当前 Host／代理声明的 X-Forwarded-Host，或 `ALLOWED_ORIGINS` 里的显式 HTTP(S) origin；不会把所有 e2b 子域或所有 LAN 域名当作可信。无 Origin 的非浏览器客户端仍必须认证／是成员。

**代理必须覆盖／剥离客户端传来的 X-Forwarded-Host 与 Forwarded 信息**，只从可信代理接受转发头；直接访问后端的公网流量应阻止。示例 Caddy 用 `{host}` 覆盖转发 Host，避免相信来路不明的值。使用 Nginx／网关时做相同处理。

可按需要在服务端配置额外已知 origin：

```dotenv
ALLOWED_ORIGINS=https://tavern.your-domain.example
```

浏览器 REST／下载用 X-Ember-Session 传应用会话，兼容占用 Authorization 的访问网关；直接 API 仍支持 Bearer。代理应转发应用头，WS 首帧传凭据，不把 token 放进 URL。

这是额外 WS origin 配置，不是开放全部 REST CORS 的开关；正常前端走同源。不要填 `*`。默认只依赖实际 Host／受信代理头，LAN 原地址也可使用。

## 5. 付费服务与邀请

密钥仅在部署机器 `.env`／环境变量；不进作品、聊天、前端或 Git。没有密钥先用明确标记的演示脚本。

体验账号不能独立启用真实模式／服务端付费 TTS；但正式房主启用真实模式后，**受邀成员的行动同样会调用部署者的模型账户**。房间邀请不是账单额度。只邀请可信同伴；到供应商侧设置预算／上限，限制部署入口。

房间 demo 只控制内置 GM；地图 AI／TTS 的显式生成可独立联网收费，不是全局断网或费用开关。

目前没有每房间费用硬额度、持久队列或供应商 exactly-once。生成后发生关闭、回档、修订冲突或服务器故障仍可能计费。回档不撤销外部调用，重试也可能再次计费。

`ENABLE_DEMO=false` 只关闭演示／游客入口，不等于禁用公开注册或已经实现账单防滥用。公网服务还需要外部访问控制、注册策略、配额与监控。

## 6. 保存、备份、恢复

数据在 DATA_DIR；默认项目 `data/`，启动器使用其独立实例数据，Docker 用持久化 `/data`。关机前正常停止服务，不要删除数据库 WAL／素材目录。

```bash
python scripts/backup.py --bundle --output backups/tavern.zip
# 先停服；恢复到新／空目录，--stopped 只是操作员确认：
python scripts/restore.py backups/tavern.zip --target data-restored --sha256 <实际SHA256> --stopped
```

bundle 包含 DB／素材／已安装插件／信任记录，不含 `.env`；密钥另用安全渠道保管。备份含账号哈希、私人剧情和可执行代码，哈希不是加密；只恢复可信来源。恢复后检查 integrity、重审插件、确认目录与配置，再启动。迁移／升级前做一次完整备份。

## 7. 故障定位

| 问题 | 优先检查 |
| --- | --- |
| 同伴无法打开 | 服务是否绑定 0.0.0.0；IP／端口；私有防火墙；访客网络隔离 |
| 邀请码无效 | 是否访问同一实例；是否轮换旧码；是否暂停邀请；人数是否满 |
| 一直重连 | WS 代理／Upgrade；Origin 与 Host；会话是否过期；是否已被移除 |
| 409 修订冲突 | 同伴已更新／回档；刷新并重新检查，不盲目覆盖 |
| 插件不可用 | 依赖、最低宿主／API 版本、哈希变更、backend 信任／能力 grant |
| 模型“已配置”但失败 | 配置只表示字段存在；检查真实模型可用性、供应商状态／余额，不能把它当联网验收 |
| 界面恢复默认 | 主题是本机 localStorage；更换浏览器／地址会用另一份偏好 |

报错提供脱敏复现和浏览器／系统版本，不上传 `.env`、token、用户 DB 或完整备份。完整信任边界见 [SECURITY](../SECURITY.md)。
