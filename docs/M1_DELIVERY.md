日期：2026-10-02。开发版本：**宿主 / 网页 2.4.0-beta.1，桌面 / Go 0.2.0-beta.3，Plugin API 1**。

按 [开发计划](DEVELOPMENT_PLAN.md) 推进，接续 [M0](M0_DELIVERY.md)。本批是可运行代码与原创样板，不把 D&D / SLG、真人质量、正式社区市场或新公开 EXE Release 冒称完成。M0 PR 尚未合并时，固定工作分支与 PR 累计保留分阶段提交，不另建未经跟踪的分支。

## 1. 已落地的闭环

**选择预设 → 校验组件 / 依赖 → 原子创建房间 → 分配四张角色 → 行动 / 线索 / 场景 → 不同结局 → 保存继续 / 回档。**

| 项目 | 本批实现 |
| --- | --- |
| 契约 | ember.preset/v1、ember.scenario/v1、ember.preset-bundle/v1，JSON Schema 与运行时 / CLI 共用 |
| 数据包 | JSON / ZIP 文本清单，精确组件 ID / 版本 / 原字节散列；禁止代码、穿越、链接、隐藏 / 重复 / 超大文件 |
| 本机库 | 私人作品按作者账号授权；散列不等于读取权限；固定 ID / 版本不可覆盖，新版旁存 |
| 来源锁 | 世界 / 剧本 / 角色 / 主题 / 规则实现 / 模块版本与 SHA；旧房间不自动更新 |
| 原子开桌 | 角色 / 成员 / 模块 flags / 来源 FK / 开场 / 创建回执同一 SQL 事务；同请求重试同房间，换意图复用 key 冲突 |
| 有限剧本 | 房主确认揭示、线索前置条件、当前节点、结局；AI / facts 文本不能改这些权威状态 |
| 多人隐私 / 回档 | 玩家与只读 UI 不接收 GM 指引 / 未来图 / 未揭示线索；节点 / 揭示 / 结局随事件快照回档 |
| 叙事玩法 | narrative 政策由服务器拒绝违规检定提议；不是只写“不要掷骰”的提示词 |
| 网页入口 | 大厅、创作工坊导入预览 / 确认；剧本与线索面板；个人主题建议不强制改变朋友界面 |
| 桌面入口 | 向导的完整玩法库、精确版本开新桌；本地文件选择器预览并确认只导入数据 |
| 创作者工具 | init preset / scenario / plugin-campaign、lock-preset、plugin-pins、validate、package-preset、schemas |
| 社区示例 | 独立 campaign-compass UI，经 core.campaign/v1 读公开进度，不改宿主注册表或 DOM |

数据导入不自动安装 / 信任插件，也不携带 API key；演示默认不调用外部主持模型，真实模式与独立 TTS 等显式生成另计。

## 3. 使用方式

### 房主

1. 新版桌面向导 → **玩法预设库**；或网页大厅 → 同名入口。
2. 选精确作品版本，检查内容提醒、许可、依赖。缺必需模块时不会创建半间房。
3. 填房间名称，默认演示；可勾选房主也操控第一位角色，或让房主只主持。
4. 给同伴身份密钥入座，分配四位角色。在冒险桌 **剧本与线索** 查看目标与公开线索；只有房主能揭示 / 推进。
5. 场景推进不替玩家选择，依据实际对话 / 行动结果确认。等待检定 / 主持时先处理完；结局不自动重开。
6. 同一实例重启后继续原房间，保持来源锁 / 角色 / 访客。回档到开场会还原节点和揭示状态，不复活已撤销权限。

旧 M0 世界 / 房间 / 独立内容导入仍可使用。新整套包只用于新房间，不一键替换已有战役。

### 作者

完整教程：[PRESET_AUTHORING.md](PRESET_AUTHORING.md)，设计决策：[PRESET_FORMAT_RFC.md](PRESET_FORMAT_RFC.md)。

```bash
python scripts/creator.py init preset creations/my-game --id my-game --name "我的玩法"
# 编辑世界、剧本、人物、署名 / 许可、readme.md
python scripts/creator.py lock-preset creations/my-game
python scripts/creator.py validate creations/my-game
python scripts/creator.py package-preset creations/my-game artifacts/my-game-1.0.0.zip
```

公开分享前核对所有来源 / 派生与许可。原生桌面 ZIP / JSON 导入要明确确认；网页同样先预览绑定散列，再写自己的数据作品库。代码模块单独打包安装；不要把 ui.js / backend.py 放进预设 ZIP。

## 4. 兼容与权限边界

- 当前仍只有 ember-light/v1，实现版本 1.1.0；变化的规则源码 / 契约散列拒绝旧锁结算，变化的模块暂不启用。不是自动保留任意旧 Python 代码的万能运行环境。
- 运行库新版旁存，旧房间仍引用原包。房主维护战役世界不会回写原作品；来源锁标识的是初始模板，而非声称运行状态永远不变化。
- 匹配且声明关闭的可选模块可以按能力开启；新增未锁定模块 / 不匹配版本需未来显式迁移方案，不静默改旧房间。
- M1 新房间 schema_version=2，旧 M0 应拒绝读取，避免不识别私有剧本而泄漏。没有 M1 私有状态的旧房间仍 v1；升级前备份，不无预检降级。
- 私人本机包按账号隔离。静态内置样板在公开源码中，不能承诺玩家不能查其谜底。真正房间秘密由服务端投影保护；模型读秘密后仍可能在生成文本泄漏，不能把真实私人资料放剧情中。
- SQL 事务不保证已受信任 Python 钩子或外部模型 / TTS 的副作用 exactly-once；本批开桌没有付费模型调用。
- 地图、美术、TTS、台本、5e / SLG 规则不被揉成 JSON 脚本。图片 / 音频包格式、任意表达式语言、旧房间迁移、跨用户凭据恢复仍另立阶段。
