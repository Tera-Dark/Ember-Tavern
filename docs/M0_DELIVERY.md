# M0 第一批交付：可恢复、少设置、开好第一桌

日期：2026-10-02。开发版本：**宿主 2.3.0-beta.2 / 桌面与部署引擎 0.2.0-beta.2 / Plugin API 1**。

这是 [开发计划](DEVELOPMENT_PLAN.md) 的第一批实现，不是 M0 全部人工验收完成，更不是 M1–M4 已实现。当前 Release 的 beta.1 不会被覆盖；普通推送 / PR 只构建新安装产物，不自动发布。

## 2. 房主的最短路径

1. 打开新的 Windows 桌面构建，创建实例；允许可信 LAN，端口无冲突即可。
2. 安装完成后自动进入 **开桌向导**。下载 / 安装进度单独显示；失败重试，不删除数据。
3. 选择“雾港 · 第十三盏灯”或“边境 · 失联的驿路”，输入房间名，**以演示创建新房间**。
4. 单人试用可直接进入；多人则为每位朋友生成身份与专属验证密钥。
5. 朋友在浏览器输入身份和密钥；入座后在向导里将角色分配给该成员。
6. 点击 **进入第一场冒险**；不确定行动由服务器提出 / 执行检定，演示不会调用外部模型。
7. 停止 / 关闭不会删除房间。下次启动同一实例，在向导中选择已有冒险继续。

向导只在本机浏览器保存所选房间 ID，**不保存验证密钥**。生成的密钥只在当次界面显示；切换页面后消失。再次生成会作废旧密钥，不把密钥加入 URL。

### 同伴入口

- 私下传递 **LAN 地址、身份、密钥**，朋友不需要 EXE 或开发环境。
- 不发送 localhost / 127.0.0.1 / 0.0.0.0 作为朋友地址。
- LAN 地址缺失时运行本机自检；检查 Wi-Fi / 网线 / VPN，允许酒馆端口的私有网络防火墙，不关闭安全软件。
- LAN HTTP 不加密。远程用 VPN / HTTPS；本轮不把沙箱的双浏览器测试称为实际 Wi-Fi / 手机设备验收。

## 3. 真实模型：从一个接口开始

默认仍是 **演示**，即使已经保存真实 API 配置也不自动切换。

- **演示 `demo`**：不调用外部主持模型；独立 TTS / 图片等显式生成另计。
- **单模型 `single`**：只需 `DECISION_BASE_URL`、`DECISION_MODEL`、`DECISION_API_KEY`。不会调用 Gemini；仍有世界书 / 事件检索上下文与服务端结构校验。
- **双模型 `live`**：知识顾问 + 决策模型，需要另外配置 Gemini；用于愿意承担额外请求的房主。

桌面停止实例 → 保存配置 → 重启 → 冒险桌“主持设置”明确选择模式。自行运行服务端则修改 `.env` 后重启。接口必须兼容 `/chat/completions`；无认证本地服务可使用其文档允许的占位 key，不需要购买额外服务。

“配置存在”不是联网 / 模型可用 / 配额已验证。失败保留已提交行动 / 骰子结果，明确显示错误，不自动降级为演示。重试外部请求可能再次计费；回档不撤销账单。本轮供应商契约由 HTTP 桩测试，没有使用真实付费 key 验证质量 / 听感。

## 4. 旧实例恢复：先保护证据，再处理

### 自动流程

- 启动只读原索引：合法条目正常加载，其他条目进入可见隔离列表。
- 首次保存前，在 `index-backups/launcher-<原文件 SHA256>.json` 保存原始字节。备份缺失 / 被修改或无法写入会阻止保存，不能静默继续。
- 隔离条目的完整原始 JSON 保存在私有索引，普通状态接口只返回名称 / ID / 原因 / 恢复状态，**不返回 raw record**。
- “复制恢复”先要求确认旧服务停止、旧端口空闲；只允许经验证的单层目录，不用坏 ID 拼路径。
- 复制到新 ID，原目录、原索引备份保留。重复请求返回同一个恢复目标，不重复生成实例。
- 不接管旧 `app/`、环境、`python-path` 或更新日志；使用当前受信任本体重新安装。已恢复的数据库即使没有旧 Python 环境也能只读快照、预检迁移后启动。

**data 中的原插件与已有信任记录也属于恢复数据。** 恢复动作不运行旧 app / 环境；后续启动新宿主仍会按现有能力 / 哈希信任校验加载原已授权插件。复制不是代码审计，也不新增第三方授权；来源不可信时先人工审阅。

### 不自动处理的情况

- `../`、绝对路径、斜线、Windows 保留名、符号链接 / junction、特殊文件。
- 目录缺失、元数据无效、重复 ID、旧目录已恢复或已被有效实例使用。
- 整体 launcher.json 损坏 / 未知未来版本、大目录、旧服务仍运行或对应关系不清楚。

此时保留整个管理目录与备份，不删除旧记录来“修复”。人工恢复：关闭服务，另做完整备份，确认真实目录 / 账号 / schema；创建新的安全实例，将可信数据副本交由匹配版本预检。不要在数据库上改 owner_id 来冒充房主。

### 房主凭据与密码边界

复制数据不等于恢复密码。桌面需要原 Windows 用户可解密的 `desktop-credentials.json`；恢复后的新 ID 会受保护地关联原账户，原关联也保留。缺失 / 解密失败 / 原登录被拒绝不重置密码、不创建替代房主。

原来手动注册的账号可以在浏览器以原账号登录。自动桌面账号的凭据如果真正丢失，本轮不能保证重新取得房主控制权；保留数据，后续需明确的离线管理员恢复 / 导出策略。普通游戏数据备份不能冒充可移植 DPAPI 凭据备份。不要用旧 beta.1 覆盖管理目录做无预检降级。

## 5. 构建与发布：源码和 EXE 必须对应

- `desktop-bundle.json`：打包来源提交、桌面 / 引擎 / 宿主版本、是否有未提交改动、打包时间、内容文件散列。桌面显示该来源，与实例实际安装版本分开。
- `desktop-smoke.json`：来自实际安装 EXE，包含对应提交 / 版本、窗口隔离、向导 / 访客 / 角色分配、游戏窗口与安全退出。
- `desktop-provenance.json`：将两份 EXE、SHA 文件和该次 smoke 的散列绑定到同一提交。
- CI 根据 `desktop/package.json` 取标签；发布前再次检查 EXE / SHA / proof / smoke，一项不一致就拒绝。
- 普通 push / PR 只留构建产物。维护者选择新版本 tag 或明确勾选 dispatch `publish=true` 才发布；已有 Release 拒绝修改，不覆盖旧 EXE。

本轮没有发布新 Release。版本号表示当前开发构建，不表示用户已下载这版。Windows 真实安装证据以本 PR 关联 CI 为准；本地 Linux 浏览器不是 native Electron / DPAPI 证据。

## 6. 验证与复现

本地已验证：后端 **121 passed**；桌面 **16 tests passed**；Go race / vet，包括真实安装更新回滚、恢复 SQLite 后首次重装；schema 无漂移；前端 / 桌面生产构建。

原有核心 / 插件 / 创作三套真实双浏览器回归也通过：权限不随回档恢复、秘密不发玩家、iframe 隔离、服务端骰子、移动端无横向溢出，页面 / 控制台错误为零。

双浏览器专项检查：真实隔离 Python 安装、选择边境世界、访客浏览器入座、向导分配角色、完成演示行动、密钥不进 URL / localStorage、自检、停止重启继续同一房间 / 访客、安全复制恢复、无页面错误。截图 / 原始报告在 ignored `artifacts/desktop-m0-evidence/`，不是源码产物。

```bash
python -m pytest -q
python scripts/creator.py schemas --check
go -C launcher test -race ./...
go -C launcher vet ./...
npm ci --prefix web && npm run build --prefix web
npm ci --prefix desktop && npm run build --prefix desktop && npm test --prefix desktop
node desktop/scripts/release-metadata.mjs versions
```

真实子进程 Go 回归需显式 `EMBER_LAUNCHER_TEST_PYTHON`，该解释器的系统 site-packages 应有锁定依赖；不要为测试放宽生产 `-I` 隔离或继承 PYTHONPATH。

向导浏览器测试需要一个新隔离预览目录，先运行 `python tests/browser_m0.py --seed`，准备真实 Go / host bundle 后用 `node desktop/scripts/preview.mjs` 启动，再运行 `python tests/browser_m0.py`；原生界面用 Windows workflow 的 `electron-smoke.cjs` 验证。不要对用户真实管理目录运行测试。
