# RFC：M1 数据玩法包与有限剧本 v1

状态：本批已实现的设计决策。日期：2026-10-02。作者操作见 [PRESET_AUTHORING.md](PRESET_AUTHORING.md)；长期约束见 [CORE_REQUIREMENTS.md](CORE_REQUIREMENTS.md)。

## 目标

完成一个可组合的开桌闭环，不把世界书提示词当规则实现，不让内容导入取得代码授权。兼容 M0 旧房间 / 旧内容格式，建立以后 5e / SLG / 模块 SDK 演进可以使用的版本和权限基础。

## 契约与运输

- 清单：`ember.preset/v1`；剧本：`ember.scenario/v1`；运输 JSON：`ember.preset-bundle/v1`。
- 清单组合既有 worldbook / character / theme v1；组件和模块声明精确 ID / 版本 / SHA256。
- ZIP 在内存逐项读取，不解压到磁盘；封闭清单、无脚本、无未知字段 / 格式、无路径穿越 / 链接 / 特殊文件；1 MiB 压缩、1.5 MiB 展开、48 文件、组件另有上限。
- 只支持 UTF-8 JSON / 说明文本。美术 / 音频打包、任意 DSL、远程资源下载留到独立格式演进，不在 v1 偷加代码语义。

## 权限与持久性

- 预览纯读取、不写库。确认绑定 `expected_hash`，同文件不能在确认阶段被替换。
- 导入只存 JSON 数据。模块缺失、版本不符、已有信任失效是兼容阻塞，不自动安装代码或新增授权。
- SQLite `preset_packages` 固定版本不可覆盖，`preset_access` 按作者账号授予本机私人作品读取权；散列不是能力令牌。内置原创样板属于公开源码，不保证玩家不能查其静态谜底。
- `room_preset_locks` 外键保留原包；房间快照 `_preset_lock` 保存来源、组件、规则实现与模块精确散列。库新版本旁存，不影响旧房间。
- 实际规则实现 / 契约不匹配拒绝结算；模块内容不匹配暂不启用，不静默迁移状态。可关闭原模块，新增未锁定模块需未来显式升级方案。

## 原子开桌与重试

单次 `BEGIN IMMEDIATE` 提交房间、成员、角色分配、模块 flags、来源 FK、开场事件和创建回执。必需依赖失败 / 写入错误回滚，不留下半间房。

`room_creation_receipts(user_id,request_key)` 绑定稳定请求内容散列；同用户同意图重试返回原房间，换配置复用 key 冲突。请求检查在限流计数前，成功后的重试不重复开桌。幂等不等于所有外部系统 exactly-once；本阶段创建无付费模型调用，已信任 Python 钩子的外部副作用不受 SQL 事务保证。

## 剧本语义

- 有限场景图、公开开场、GM 指引、稳定线索、线索集合前置条件、明确结局。
- 房主命令揭示 / 推进；当前 scene_id、revision、权限和幂等回执校验，等待检定 / 主持期间拒绝推进。
- AI 提议 / facts 文本不修改 revealed_clues，不绕过路线条件、不自动决定结局。narrative 检定政策由服务器拒绝违规模型提议，而非只写提示词。
- 场景、揭示与结局在快照中回档；权限撤销不随剧情回档复活。模型只获当前节点的预算内私有片段，不注入整个未来图。
- M1 房间 schema_version=2：M0 应拒绝加载，避免不识别私有 `_scenario` 的旧投影泄漏。没有 M1 私有状态的旧房间仍保持 v1。升级前备份；不无预检降级 M1 存档。

## 模块边界

`core.campaign/v1` 是公开只读资源，能力 `read:room`，包含当前场景 / 目标 / 已揭示线索。GM 操作经宿主命令，不允许普通 UI / namespace 写直接修改该资源。`campaign-compass` 独立只读 UI 样板无需宿主注册名字；它是插件包，不能嵌入预设 ZIP。

## 未实现的扩张

- 新规则注册、完整 D&D / CoC / SLG、任意属性 / 经济 DSL、全自动 AI 剧情导演。
- 对已有房间一键切规则 / 更新依赖，完整迁移 / 降级、跨机凭据恢复。
- 付费模型预算账本、无限记忆、向量检索、云多租户和商业市场。
- 未授权素材的再分发；官方样板暂标 UNLICENSED，许可由拥有者决定。
