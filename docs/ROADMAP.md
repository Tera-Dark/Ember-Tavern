## 已落地的基础

- 同一服务器的账户／房间／邀请／操控权，邀请暂停／轮换、移除／退出、会话感知 WS。
- 服务器权威 ember-light/v1 判定，AI／人工主持，完整事件／分支回档；运营权限不回档。
- 世界书与角色卡的 v1 契约／预览／有修订与幂等的导入／导出；公共与主持资料分流。
- 规则／常驻／关键词／词法激活、上下文预算与房主无费用预览；有效分支记忆。
- 数据型配色主题、共享令牌；隔离 UI／可信 Python SDK、声明能力、资源、依赖、namespace 与哈希授权。
- 世界／角色／主题及三类插件脚手架；共享校验／四个生成 Schema／自动测试／浏览器验收入口。
- 地图、移动、台本与 TTS 的既有独立模块，新增骰盘调用权威宿主命令的模板。

## P0：你们真实跑一场（下一步最重要）

| 工作 | 验收标准 |
| --- | --- |
| 2–4 人 LAN／VPN 完整试玩 | 建房 → 自己的世界书 → 分配角色 → 多轮行动／检定 → 断线回归 → 回档 → 关机／再启动，全程不丢权威记录 |
| 选定一个实际规则玩法 | 先明确是否继续轻规则，或哪一个系统／版本；不同时承诺所有规则 |
| 真实模型／TTS 小额验收 | 用户在服务端配置 key；失败可恢复；确认可用模型、账单、中文音频与隐私；测试密钥不进 CI |
| 升级与跨平台检查 | 真 Windows 启动器／Docker／备份恢复实机验收；保持单 worker，不把文档命令当已测 |
| 发布法律边界 | 仓库拥有者选择正式 LICENSE；模板／规则／图片授权真实明确；补齐多来源署名，不把 example 当自动授权 |

## P1：小团体长期使用

1. **费用与可靠性优先**：房间／用户调用额度、生成前确认、费用估算区分 token 与字符；持久任务状态、供应商幂等支持、超时取消、失败恢复。验收必须涵盖重复请求、断电、回档和已计费未提交。
2. **主持工作台**：更清晰的 GM 屏幕、NPC／任务／玩家个人便签权限模型、剧情事实确认／摘要审阅。跨插件资源的细粒度可见等级／消费方能力模型也要在这里明确，uses 声明不是自动的私有 ACL。新增私密字段先实现 REST／WS／历史／搜索／插件投影测试，再做 UI。
3. **素材底座**：不可变图片／头像／地图资产、MIME 验证、引用权限、上传／存储额度、备份与无引用 GC；主题布局／美术包引用这层，而不是允许任意 CSS／远程脚本。
4. **创作体验**：世界条目全文编辑、拆分／搜索／冲突差异、导入转换后编辑、导出作品 metadata 编辑、多来源／逐条出处和许可记录。明确支持的 ST／角色卡子集，测试真实用户文件。
5. **房间生命周期**：房主转让／删除、封禁及隐私删除策略、账号恢复、邀请有效期／次数；安全策略不放进可回档剧情。

## P2：完整玩法和可审查生态

- **选定规则 adapter**：独立角色／检定／Decision schema、纯规则计算、迁移、骰子与边界 fixture；换系统先检查已有角色，禁止换个字符串就宣称完整兼容。
- **地图路线**：无网格／战术网格可替换 renderer；先攻、路径／距离、视线／战争迷雾按明确契约逐步加入，别让地图模块接管角色权限。
- **声音路线**：多角色 voice、播放调度、字幕、失败重试；支持服务商独立适配，不让脚本编辑改正史或隐含收费。
- **发布路线**：真实 Release ZIP／SHA、版本兼容矩阵、维护者／审核记录／撤销信息；依赖版本范围、迁移演练、签名与可追溯 provenance。先人工审查再讨论商店，不把未知 GitHub Python 自动执行。
- **更大知识库**：可替换检索 provider、索引／向量检索、主持可解释预览、分支隔离、可审阅长程摘要；缓存与索引必须随着回档失效。

## 更远：只有规模需要时才升级基础设施

PostgreSQL／共享协调／消息总线、多 worker、素材对象存储、完整可观测性、账号验证／部署隔离、配额和灾备。迁移前定义幂等、锁、广播与权限一致性验收；当前 SQLite 单实例并不需要先改成集群。

## 每个新模块的进入标准

- 清单、能力、资源 `/vN`、依赖、最低宿主与 state migration 说明；社区默认关闭。
- 谁能读、谁能写、是否付费、关闭是否保留、回档怎么处理，有明确答案。
- 不改 core 数据库；公共／GM 投影失败关闭；输入、网络、体积、异步修订有边界。
- 旧状态／重复请求／并发／失败／回档／手机测试；标出未验证的平台与供应商。
- 作者／源码／许可／实际包 SHA；不能把哈希说成代码安全审计。
