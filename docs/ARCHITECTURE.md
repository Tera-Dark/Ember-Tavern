# 余烬酒馆：小团体跑团与创作生态架构

宿主 **2.2.0-beta.1** · Plugin API **1** · 内容格式 **v1** · 2026-09-30

## 1. 先把边界划清，而不是把功能塞满

主要场景是一位房主与几位朋友，共用一台服务器进行中文跑团。本轮提供可运行、可测试的基础，不宣称完整 D&D／CoC、成熟在线市场或公网商业 VTT。

三个原则：

1. **宿主掌握权威状态和访问权限。** AI 给结构化提议，插件提交自己空间的数据，客户端显示／发送意图；掷骰、属性后果、成员身份与提交冲突由服务器处理。
2. **内容、表现、执行规则分离。** 世界书／角色卡是可交换 JSON，主题是个人配色，地图／声音是插件，可执行规则是经过审阅的规则适配器。世界书文字不能安装 Python、重写权限或注册规则引擎。
3. **同一条资料从导入到 AI、玩家、插件和回档都有明确路径。** 主持秘密不能只在 React 中隐藏；运营权限不能因回档复活。

## 2. 分层与代码边界

```text
浏览器：React 宿主 UI ─── 独立 sandbox 插件 UI
                 │ 同源 REST / WebSocket / 能力桥
                 ▼
server/app.py：组合根、游戏命令、GM 生命周期
 ├─ routes/             认证、房间、角色／世界、历史、成员管理
 ├─ content/            校验 → 兼容转换 → 预览 → 修订检查 → 导入／导出
 ├─ contracts/          内容、插件、GM 输出、保留资源的共享契约
 ├─ runtime.py          权限、锁、幂等回执、会话感知广播、房间投影
 ├─ projection.py       主持／玩家数据投影
 ├─ state.py            核心状态版本与旧快照迁移
 ├─ rules/              ember-light/v1 权威判定
 ├─ retrieval.py + ai.py 激活／预算／有效记忆／供应商适配
 └─ plugin_runtime/     清单、依赖图、独立 namespace、SDK、信任
                 ▼
SQLite WAL：游戏快照 + 事件 + 运营关系／配置
DATA_DIR：不可变素材 + 已安装插件 + 审阅哈希
```

`server/app.py` 保留原游戏 API 与测试替换入口，避免为了拆文件而打断已有流程；它不是所有扩展功能的实现地点。前端公共 UI 在 `web/src/components/`，创作／外观／邀请在 `web/src/content/`；第三方 UI 经 `PluginHost.jsx` 自动导航，不需要修改 App 或重新构建宿主。

## 3. 领域对象与权限

| 对象 | 权威来源 | 修改者／可见性 |
| --- | --- | --- |
| User / Session | 数据库；带过期时间的 bearer 会话 | 各自登录；供应商密钥只在服务端 |
| Room / Members | 数据库关系 | 房主邀请、移除；玩家退出；仅成员可读房间 |
| Assignment | 独立关系表 | 房主分配；每人一个角色；玩家只控制自己 |
| World / Lore | 核心游戏快照 | 房主写；公共条目供成员，`gm` 条目仅房主／主持上下文 |
| Character | 核心游戏快照 | 成员查看公共档案；`gm_notes` 不发给玩家 |
| Continuation / PendingCheck | 服务器游戏状态 | 玩家提交行动；服务器校验提议、掷骰、扣生命／加压力 |
| Event / Snapshot / Branch | 追加事件、完整游戏快照 | 房主回档；旧未来封存，不进当前 AI 记忆 |
| Plugin Namespace | `_plugins[id]` | 插件只通过 Result 提交自己的空间 |
| Theme Pack | 浏览器 localStorage | 每位用户本机选择，不改变房间／剧情 |
| Import Provenance | 主持侧 `_content.sources` | 最近 20 次来源元数据／哈希；不是完整版权数据库 |

这里没有玩家私密背包、私人聊天或逐条角色字段 ACL：除 `gm_notes` 外，角色资料共享；`extensions` 默认共享，不能用来藏私人信息。服务器管理员与受信任 Python 插件能读取服务器数据，不属于玩家隔离边界之外的保密保证。

### 回档恢复什么？

恢复：世界书、角色属性／物品／主持备注、规则描述、场景、事实、待检定与插件 namespace／素材引用。旧快照在读取／回档时运行核心迁移。

不恢复：成员、角色操控权、模块开关、邀请开放状态和邀请码。角色分配从当前关系表重建，不从历史快照读取。回档后 branch 增加；异步插件操作必须验证分支，不能把旧未来重新写回来。

素材文件不可变，回档只是改变有效引用；不会撤销已下载数据或外部服务收费，也还没有素材 GC。

## 4. 四条端到端流程

### 内容创作／导入

模板／文件 → 大小与结构限制 → 原生格式或显式兼容转换 → Pydantic 契约 → 提示与变更预览 → 房主确认 → 锁／权限／revision／request_key 再校验 → 事件 + 快照 + 回执同事务 → 按查看者广播。

- 标准格式：`ember.worldbook/v1`、`ember.character/v1`、`ember.theme/v1`；未知版本不猜测降级。
- API 写请求体在解析前限 2 MiB；创作 JSON 限 512 KiB、16 层、20,000 节点；世界数据另限 384 KiB／160 条。
- 世界书合并按条目 ID 更新，保留现有名称／前提／规则；替换只替换世界书，不清空剧情、角色或事实。另开新冒险请新建房间。
- 角色卡无运行时 ID／操控者；导入生成新角色，保持未分配。
- 预览不写游戏数据、不调用模型；提交仍重新验证，旧预览不能覆盖新房间。
- 所有运行时校验、CLI、安装器和四个生成 Schema 共用契约；Schema 不能替代跨字段、总字节等语义校验。

### 玩家行动／AI 主持

操控权与修订检查 → 保存行动／continuation → 广播等待状态 → 当前启用 GM 提供者 → 有预算的上下文 → 结构化 Decision **及 GMTrace 校验** → 服务器规则适配器 → 保存叙事／检定提议 → 按查看者广播。

GM 流程持有游戏锁；独立插件可在自己的锁下更新 namespace。提交 GM 事件时保留其他插件已经提交的数据。模型失败不冒充成功，也不暗中切为演示：已保存行动／骰子保留，房主可重试或人工补述。重启后未完成主持显示恢复提示，尚无持久任务队列。

当前只有 `ember-light/v1`：d20 + 属性、天然 1／20、难度 8–20、生命／压力风险；服务器生成随机数。文字桌面约定可作为 `kind=rule` 输入，但不能改变判定算法。添加新的系统需要新 adapter、角色／Decision 契约、迁移和回归测试；不开放任意 JSON 表达式执行。

### AI 记忆与秘密

1. 保留当前行动／骰子、所有角色结构化属性、当前场景与近期有效叙事。
2. 排除停用条目；规则／常驻优先，其次字面关键词，再词法相关度；同级参考 priority。
3. 最多选择 32 条世界条目。默认整体 24,000／世界条目 6,000 序列化字符，整体配置约束 8,000–96,000；不是 token 数或费用估算；预算控制游戏上下文，模型 system／Schema／知识顾问文本另计。
4. 加入当前分支事实和历史事件；排除封存未来、场外聊天、来源元数据与插件／vendor 任意转储。
5. `_selection` 诊断留给房主，不进入提示词；GMTrace 不接受任意 prompt／debug 字段。

REST、WS、历史、检索与插件上下文均服务端投影。`read:room` 插件即使被房主打开也只获得公共数据；`read:gm` 必须部署者显式授予，并仍只对房主开放。`core.*` UI 资源永远采用公共投影。非核心资源由可信提供者定义公开语义，uses 不是通用私有资源 ACL；不要把私密 namespace 直接提供给任意消费插件。

**秘密边界有两个层面：**服务器可控制发给哪个客户端；真实模型看到主持秘密后是否在公开叙事中透露，只能通过提示、输出约束与人工检查降低风险，不能保证绝不泄露。真正敏感的个人信息和凭据不要放进世界书。已经公开／下载过的内容不能靠改权限撤回。

### 插件／表现层

审阅包 → ZIP／路径／清单校验 → 哈希绑定的显式授权 → 发现与版本检查 → 房主按房间开启 → 依赖／唯一资源／唯一 GM 检查 → sandbox UI 或可信 Python → 受限 Result／能力桥 → 事件／快照。

- 同时允许一个 GM 提供者、每个版本化资源一个启用提供者；依赖健康传递检查。
- 插件不能提供 `core.*`。保留资源与权限在 `contracts/resources.py` 统一定义。
- `EmberSDK.roll()` 调宿主权威自由骰，不能完成／伪造待检定；`source_plugin` 与 request_key 可审计。
- 一般插件操作核验 namespace revision／依赖 revision／branch；读取核心资源还核验房间 revision。关闭保留状态，角色权限和回档仍由宿主处理。
- 瞬态 signal 用于拖动预览，不生成持久事件；松手 action 才提交。
- 主题只允许 15 个十六进制颜色令牌、dark／light；不载 CSS、脚本、字体 URL 或图片 URL。配色转发给隔离 UI，UI 作者负责使用令牌。
- 地图、台本、TTS 已有独立模块；美术资产库、完整战棋和新规则 adapter 是后续模块，不是假装本轮完成。

## 5. 版本与发布约定

| 层 | 本轮 | 演进方法 |
| --- | --- | --- |
| 宿主应用 | 2.2.0-beta.1 | central `server/version.py`；前端／部署 manifest 同步 |
| Plugin API | 1 | 破坏性 SDK 变更才升主版本；能力新增与最低宿主版本分开 |
| Plugin minimum_host | 三段数字；默认 2.1.0 | 比较宿主数字基版；beta 后缀不参与，因此 2.2 beta 可满足 2.2.0 |
| 插件 state_version | 独立整数 | 作者 migrate；测试旧 namespace 与回档快照 |
| 核心 schema_version | 1 | 核心单调迁移；未来未知版本拒绝启动／读取 |
| 内容／资源 format | `/v1` | 不兼容结构新 `/vN`；内容不悄悄注册代码 |
| 作者发行 version | 三段数字，最多 32 字符 | 作品迭代与格式版本分开；不是依赖范围求解器 |

不兼容最低宿主或 Plugin API 的包不会执行，即使有信任记录。哈希变化撤销新的调用授权；已经执行的 Python 副作用无法撤回，升级／移除后端时停服并重启。

## 6. 运行与安全约束

- 单服务器、**单 worker**、SQLite WAL、进程内锁／WS，最多 12 位成员／12 个角色。不支持多实例独立同步或横向扩容。
- 同伴访问同一服务器的 LAN IP／VPN 地址／HTTPS 域名。邀请链接根据当前访问 origin 生成；本机 localhost 链接会提示不能直接给同伴用。
- 邀请可暂停、轮换；移除／退出解除分配、立即关闭 WS，登出撤销会话连接；移除不是永久封禁。
- WS 检查同源 Host／受信代理 X-Forwarded-Host 或显式 ALLOWED_ORIGINS；不能信任客户端自行提供的代理头。详见 [LAN 部署](LAN_DEPLOYMENT.md)。
- 正式房主开真实模式后，受邀成员行动也会调用部署者配置的模型。数据库幂等不等于供应商 exactly-once；当前无费用硬额度。小团体先用演示模式、公网前先做费用与访问控制。
- 完整备份包含 DB、素材、插件、信任哈希；密钥另行安全保管。备份不是加密；恢复到新目录，先审可执行插件。
