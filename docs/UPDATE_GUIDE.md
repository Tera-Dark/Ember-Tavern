# GitHub 更新与版本管理

实现基线：桌面 / Go 部署引擎 `0.2.0-beta.4`，宿主仍为 `2.4.0-beta.1`。这是源码与本地开发构建，尚未发布新的 GitHub 安装包。

## 使用

标题栏打开“更新与版本”。桌面启动时及每六小时读取固定仓库 `Tera-Dark/Ember-Tavern` 的公开 Releases；页面也可以手动检查。包含 beta / rc，排除 draft 和插件发行，按语义版本排序，不依赖会忽略预发布的 `/releases/latest`。支持分页，查询失败单独显示，不能当作“已是最新版”。

- **立即更新桌面**：下载安装版或便携版对应的 EXE 和 `.sha256`，核对文件名、大小与散列后停止部署引擎及实例，等待当前桌面退出，再安装 / 替换并重启，自动重新启动切换前运行的实例。实例、配置与加密房主凭据位于安装目录外，保留原位。正在安装或更新实例时不能切换桌面。
- **切换桌面版本**：选择已发布版本。缺少匹配安装包或校验文件的历史版本会显示但不能直接安装。便携模式使用 `PORTABLE_EXECUTABLE_FILE` 指向的外层 EXE；替换前保留 `.previous.exe`，等待文件占用解除，替换 / 启动失败会尝试恢复原文件。安装版运行 NSIS 静默安装到当前目录。
- **更新 / 切换游戏本体**：在版本页选中实例，更新到发行版或选择历史 tag。默认随包实例的检查也查询 GitHub，不再只读包内版本。main 实例继续跟踪 main；指定发行版切换成功后进入 release 通道。下载固定 tag 对应的完整 commit ZIP，检查部署协议、最低引擎版本、依赖、数据迁移和健康状态，失败恢复代码 / 数据 / 环境与原运行状态。
- **主动回退**：成功回退后不再提示已知的同一个桌面新版；偏好保存在共享数据目录 `desktop-updates.json`，重启仍生效。以后更高版本发布会再次提示，手动升级仍可用。失败的回退不关闭提示。通过安装器自行重新安装旧版，也会根据已记录的最后运行版本识别回退。本体使用实例索引中的 `ignored_update` 记住被忽略的 commit；新 commit 再次提示。

桌面历史版本和本体历史版本分别管理。只回退桌面不自动降级实例；需要回退游戏本体时在该实例的版本页操作。

## 本体数据回退

切换前保存当前版本的数据快照至 `instances/<id>/version-data/<commit>/data`，并记录版本元数据。同一版本多次离开会保留旧快照目录，暂不自动清理。

降级优先使用目标版本离开时的数据，较新版本的进度保存在另一份快照及更新前备份中。没有目标快照时尝试在数据副本上预检；旧版不能读取现有状态则失败，不能假称降级成功。回退到旧快照会恢复当时数据库中的房间、成员、邀请等数据，不等同于冒险桌内的剧情回档。切换前请理解这点；较新内容没有被覆盖删除，但不会自动合并到旧版。

实例任务 / 日志仍显示准备、下载、备份、迁移、启停和失败原因。桌面安装辅助程序失败时写入共享数据目录 `desktop-update-error.log`。如果辅助安装失败没有重启，重新打开原桌面并查看此文件；NSIS 失败不保证自动恢复整个桌面安装目录。桌面回退不会降低本体数据格式，也不会自动撤销已升级的本体。

## 历史安装包与发布约定

已经公开的旧 EXE 如果没有 GitHub 自更新逻辑，不能通过仓库更新凭空获得该功能。尤其是 `desktop-v0.2.0-beta.1` 及早期 Go 启动器，需要先升级一次到包含本底座的安装包。回退到不包含本底座的早期桌面，也会失去版本页；需要重新运行新版安装器。从本基线继续发行的安装包保留统一入口和共享偏好，旧版本无需追随新版修改安装源。

GitHub 发行使用 `desktop-v<版本>`，并提供：

1. `ember-desktop-<版本>-x64-setup.exe` 与同名 `.sha256`。
2. `ember-desktop-<版本>-x64-portable.exe` 与同名 `.sha256`。
3. 已有工作流生成的 `desktop-provenance.json` 与 Windows 安装冒烟报告。

发行 tag 必须指向实际构建提交，不覆盖旧资产。自更新基于固定仓库、HTTPS 与该发行的 SHA256；散列不是第三方代码安全审查或代码签名。代码签名状态仍由发行说明决定。

本体支持 `desktop-v<版本>` 与历史宿主 `v<版本>`。集成桌面发行优先，分别在各版本序列内排序；真实宿主版本来自该 commit 的 `launcher-manifest.json`。当前引擎不兼容未来部署协议时，应先更新桌面。多个实例共用五分钟的 GitHub 解析缓存，避免启动时耗尽匿名 API 配额；网络 / 限流失败短期缓存三十秒，保留现有版本，可以稍后再检查。

## 验证入口

`npm run build --prefix desktop`、`npm test --prefix desktop` 验证版本排序、分页、回退提示持久化、后续新版提醒、坏散列 / 截断文件、下载地址 / 重定向约束和 Windows 辅助脚本。

`go test ./...` 与 `go vet ./...` 在 `launcher/` 执行。设置 `EMBER_LAUNCHER_TEST_PYTHON` 为具备 FastAPI / uvicorn / httpx 的 Python 后，额外运行真实 venv、子进程、服务切换与数据快照恢复。Windows 安装 / 便携完整替换和 GitHub 新发行仍须使用实际发行包验收，单元测试不替代这些结果。
