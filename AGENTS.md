# Project rules

- Keep the host modular: ordinary plugins and data presets use public contracts rather than hard-coded host navigation.
- Preserve single-worker FastAPI / SQLite operation and per-viewer REST / WebSocket privacy projections.
- Preserve existing room content hashes, rule versions and plugin pins. Version changes must be explicit and reversible.
- Python plugins are trusted server code. Catalog review, SHA256 checks and ZIP inspection do not grant execution trust.
- Never commit provider keys, `.env`, private profiles, databases, user drafts, backups or generated installers. Private test profiles live outside this repository.
- Keep `.gitattributes` LF normalization. Do not regenerate builtin review locks to hide a checkout newline mismatch or unreviewed code change.
- Shared schemas are generated by `python scripts/creator.py schemas`; check drift and local catalog integrity before submission.
- Use a `codex/` work branch and a PR for repository updates. Check actual GitHub Actions before merging; never replace published release assets.
- Source updates and public installer releases are separate. Report exact source commits, test results and remaining verification gaps.
- Repository tests use isolated data and synthetic credentials. External trials follow the owner's current instructions; no paid provider calls without applicable authorization.

Read [CONTRIBUTING.md](CONTRIBUTING.md), [architecture](docs/ARCHITECTURE.md), [security](SECURITY.md), [publishing](docs/GITHUB_PUBLISH.md) and [snapshot testing](docs/SNAPSHOT_TESTING.md) for the corresponding work.
